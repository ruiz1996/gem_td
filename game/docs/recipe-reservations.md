# 合成材料预留提示

更新：2026-09-10。用于选择保留时判断材料储备，也用于查看已保留塔的后续合成。电脑选择面板与手机操作弹框使用同一组件。

## 玩家看到的内容

- 同种、同品质宝石在场上已保留的数量，可展开查看坐标。
- 相关配方逐项标记「本颗」「已留 N」「缺 N」，多个同类材料按实际需求计数。
- 普通候选宝石标记「保留后可合成」或「保留后还缺 N 颗」。已保留宝石显示当前合成进度。
- 若本轮五颗候选已满足配方，另显示「本轮可直接合成 · 选材料」按钮，仍通过原有材料选择流程确认。
- 「材料位置与本轮候选」可展开查看材料全名、需求数量、已保留材料的列行坐标，以及其他候选的位置。
- 能立即合成的配方优先，其次是保留后可合成的配方；普通配方优先于其余隐藏配方，同组内缺少材料更少的优先。

## 计数口径

这里的「预留」指场上已经保留、尚未消耗的宝石塔，不新增手动锁定或标记机制。品质必须精确匹配，低级或高级同种宝石不会替代配方要求。

普通候选的保留预测只统计 **当前选中的这一颗 + 之前已保留的材料**。本轮其他候选不会计入预测，因为选择保留时它们会变成石头。预测按原品质保留计算，不预测敲碎的随机结果或同类融合后的品质。

当前能否直接合成仍由引擎 `recommend` 判断，不允许混用候选与已保留材料。因此同一配方可能同时出现「保留后还缺 2 颗」和「本轮可直接合成」：前者是单独保留后的库存，后者是消耗本轮候选的合成路径。

隐藏配方仅统计本轮候选，已保留材料即使品质完全匹配也不适用。选中已保留塔时，对应隐藏配方会明确标记「仅限本轮候选」。

材料数量按配方类型分组；当前选中塔只计入一次。同种多余材料会显示真实库存数量，但不能抵消其他种类的缺口。位置统一使用从 1 开始的「列、行」，与棋盘一致。

## 实现与验证

- `lib/game/recipe-progress.ts`：无副作用的库存统计与保留预测，不修改引擎、随机数、合成规则或存档结构。
- `components/game/recipe-hints.tsx`：电脑和手机共用的配方、数量、坐标提示。
- `tests/recipe-progress.test.ts`：保留后战斗合成、本轮材料与预留隔离、未建满时预测、隐藏限制、重复需求、精确品质与排序。

验证：112 项测试、类型检查、修改文件 lint 和 Pages 构建通过。浏览器检查了电脑实际选择面板、390 像素手机弹框和 320 像素窄屏；无横向溢出。独立测试场景验证了展开坐标、保留后入口切换、战斗确认合成及成品后续配方刷新，不读写玩家存档。此记录不等于安卓真机验收。
