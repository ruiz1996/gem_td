Boss扣血严格按原脚本的整数百分比两次向下取整：

```text
已损失百分比 = floor((最大生命 - 剩余生命) / 最大生命 * 100)
扣血 = floor(80 * (100 - 已损失百分比) / 100) + 10
```

## 本地验证

- 33项规则与地图测试：包括手选重复材料、合成占用不变、暂停仍禁改路、存档确定性、显隐、品质经验、Boss扣血、当波数量锁定、独立毒层最后一跳、纯粹溅射及高攻速计时。
- 50波状态转换测试使用超高伤害、全图射程和显隐的测试夹具，**只验证状态流程，不能证明正常通关**。
- 浏览器实操尺寸：默认桌面、390×844竖屏、844×390横屏；测试后恢复默认尺寸。这是桌面浏览器尺寸模拟，未连接安卓真机。
- 实操完成：旧版本存档拒绝并保留；开始新局；竖屏缩放到150%；放置5颗；2颗D1融合为D2，其余候选变石；战斗暂停后拆石按钮仍禁用；2倍速战斗；第一波结束生命100、金币25、经验25、进入第2波；波间拆石；图鉴搜索“白银”；刷新后恢复第2波及资源。
- 手选配方材料及战斗合成由规则回归覆盖；本轮自然随机实操未凑齐高级配方，没有把它记为浏览器已验收。
- 编辑中间态曾触发热更新导入错误，完成修改后重新载入。正式实操后段（06:25 UTC以后）的浏览器错误日志为空。
- 5个固定种子的简单中心布局策略均在第10波失败；详见 [`reports/balance-smoke.json`](../reports/balance-smoke.json)。它缺少合理长迷宫和配方规划。保留真实失败结果，不通过修改原版Boss数值来让这个策略通关。
- TypeScript类型检查、静态生产构建及修改文件的lint均检查；以本次终端最终结果为准。Phaser独立资源块仍较大，安卓真实加载与帧率待测。

## 还原边界与后续优先级

1. 当前工作坊版本与2018快照的差异尚未核实。现阶段应称“2018脚本基线校准版”。
2. 英雄技能与合作按用户要求不加入；使用原版击杀经验驱动品质是无英雄外观下的等价成长。金币按原数值累计，商店/石板消费尚未实现。
3. 稀有精英、180秒后的狂暴、怪物缴械/折射/反应装甲等特殊能力、石板、降级与隐藏配方的触发条件仍未完整还原。
4. 闪电链0.2秒跳跃、叉状闪电锥形范围、多重箭附加攻击的命中特效、灼烧光环离开后的残留时间仍有简化。技能原参数已存档，不代表所有执行细节已实现。
5. B/P不同等级减益目前仍采用最强值策略；Dota引擎对不同modifier叠加、刷新顺序和免疫的行为需进一步验证。护甲公式、最低移动速度和投射物飞行时间仍是模拟器约定。
6. 核验正常攻略与迷宫策略后再评估无英雄版本是否需要单独难度档；不把首关实操、状态机测试或简单布局失败当作50波平衡结论。
7. 存档结构已经变更；旧版不强行迁移，新局会替代当前浏览器存档。公开页面更新后同样执行新版本存档检查。

## 复现

在 `game/` 中运行：

```powershell
npm run data:original
npm test
npm run typecheck
npm run balance:check
npm run build:pages
npx vite --config vite.pages.config.ts --host 0.0.0.0
```

开发页面地址由服务器输出，当前默认路径为 `/gem_td/`。同一局不应混用不同版本的开发热更新；涉及状态结构更新后刷新并开始新局。
