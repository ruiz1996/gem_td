# 手机交互设计与本地验证

日期：2026-09-07。触发需求：用户反馈整个桌面交互无法适配手机，要求识别手机后使用另一套操作模式。

## 问题与方案

此前只通过响应式布局将桌面侧栏挪到棋盘下方，棋盘与确认按钮需要来回滚动。37×37全图在窄屏上格子过小，合成也依赖点中棋盘材料。本次将手机操作区与桌面侧栏分开实现，共用规则引擎。

| 场景 | 手机操作 |
| --- | --- |
| 竖屏/横屏 | 底部/右侧固定面板；棋盘与主操作保持在同一视口内，适配安全区域 |
| 镜头 | 初始以约30 CSS像素一格放大；可拖动、双指缩放、按钮缩放或查看全图；极小棋盘受12倍上限限制 |
| 建造 | 点格子定位，四个方向按钮逐格微调，独立按钮确认放置；无效位置显示提示，不揭晓宝石 |
| 五颗候选 | 五个大按钮展示类型与品质，点击选中并定位；保留或同品质融合直接操作 |
| 查找塔 | 宝石列表以名称、候选/保留状态和坐标列出，点击定位并恢复局部放大 |
| 详情和配方 | 单独详情面板，可滚动查看，顶部保留返回棋盘按钮 |
| 合成预览 | 原生选择框选择材料槽、再按坐标与实例ID选择材料；成品位置锁定，可取消后从另一颗发起 |
| 战斗 | 固定暂停/继续和倍速按钮；石头在波间可拆，战斗中不可拆；合成仍调用原规则 |
| 设置 | 自动识别、手机触屏、电脑桌面三档；切换不会重开游戏；偏好可保存 |

## 检测与代码边界

- 自动识别：视口宽度不超过600 CSS像素，或设备支持粗指针/触摸且视口短边不超过600像素。兼顾手机旋转，避免把大屏触控电脑自动判为手机。平板、折叠屏或浏览器“桌面网站”模式可能需要手动选择。
- `hooks/use-game-interaction.ts` 使用浏览器外部状态订阅；存储键为 `gemtd-interaction-mode`。不会修改游戏存档键或规则版本。
- `lib/game/interaction.ts` 集中维护识别、缩放和格子定位数学；`components/game/touch-controls.tsx` 负责触屏操作区。
- `lib/game/board-input.ts` 统一处理鼠标、笔和触摸；Phaser自身鼠标/触摸处理关闭，避免重复消费输入。触摸移动12像素以上视为拖动；发生双指、取消或失去捕获后，不把松手当成点击。
- 缩放以手势中点为锚点。棋盘仅绘制可见网格，并跳过屏幕外文字，减少放大时的绘制工作。
- 游戏规则、原版数值和DATA_VERSION保持不变；材料推荐、重复实例校验、占用保持及准备/战斗权限仍由引擎负责。

## 验证限度

上述界面实操在桌面浏览器中设置手机视口尺寸完成；Pointer Events多指与中断流程使用自动事件测试。配方实例去重、手动选择未被消耗的重复材料、战斗合成占用不变由既有规则测试覆盖。本次自然抽石局没有同种替代材料，未在浏览器中实际切换到另一颗同种材料。

尚未连接安卓真机，不能视为完成触屏硬件、浏览器地址栏伸缩、软键盘、手势返回、刘海区域和长期性能验收。没有增加APK或离线缓存。公开测试沿用[GitHub Pages](https://ruiz1996.github.io/gem_td/)，部署以[Actions](https://github.com/ruiz1996/gem_td/actions)结果为准。
