# 手机交互设计与本地验证

日期：2026-09-07。当前为第二次手机交互调整：用户认为常驻面板仍挤占地图，要求选中位置后按按钮弹出操作框。第一版固定底部/右侧面板已替代。

## 问题与方案

最早的手机布局只是将桌面侧栏挪到棋盘下方；第一版触屏界面改成常驻操作区，但用户仍认为地图空间不足。当前将整个游玩区域交给棋盘，操作框只在明确点按后出现，桌面侧栏保持原状。

| 场景 | 手机操作 |
| --- | --- |
| 竖屏/横屏 | 整个游玩区域用于地图；无固定右栏或底部操作区，适配安全区域 |
| 镜头 | 默认全图等比居中；双指缩放、放大后拖动；菜单也提供缩放。选中宝石不再自动放大。放大后地图上有“全图”入口 |
| 建造 | 点格子→点“操作”→建造框，可逐格微调→确认建造→关闭并回到地图；无效位置不揭晓宝石 |
| 五颗候选 | 在地图选择已建造宝石，再点“操作”，弹窗内“保留并开始本波”直接留石并开波；未建满五颗时禁用。也可选择同品质融合 |
| 查找塔 | 菜单内保留宝石列表，以名称、状态和坐标选择，再回图点“操作” |
| 详情和配方 | 同一个宝石操作框展示属性与配方；内容可滚动，底部“返回地图”保持可见 |
| 合成预览 | 在弹窗内选择配方，原生选择框选择材料槽、再按坐标与实例ID选材；成品位置锁定。确认或取消关闭弹窗 |
| 战斗 | 保留成功立即开波；同品质融合或本轮配方合成后仍可手动开波。战斗中点选已保留宝石可按配方合成。暂停/倍速收在菜单，操作框关闭恢复此前状态；后台仍保持暂停 |
| 设置 | 自动识别、手机触屏、电脑桌面三档；切换不会重开游戏；偏好可保存 |

## 检测与代码边界

- 自动识别：视口宽度不超过600 CSS像素，或设备支持粗指针/触摸且视口短边不超过600像素。兼顾手机旋转，避免把大屏触控电脑自动判为手机。平板、折叠屏或浏览器“桌面网站”模式可能需要手动选择。
- `hooks/use-game-interaction.ts` 使用浏览器外部状态订阅；存储键为 `gemtd-interaction-mode`。不会修改游戏存档键或规则版本。
- `lib/game/interaction.ts` 集中维护识别、缩放和格子定位数学；`components/game/touch-controls.tsx` 只在操作弹窗中挂载。现有Dialog管理焦点、关闭和遮罩，地图尺寸不随弹窗开闭改变。
- `lib/game/board-input.ts` 统一处理鼠标、笔和触摸；Phaser自身鼠标/触摸处理关闭，避免重复消费输入。触摸移动12像素以上视为拖动；发生双指、取消或失去捕获后，不把松手当成点击。
- 缩放以手势中点为锚点。棋盘仅绘制可见网格，并跳过屏幕外文字，减少放大时的绘制工作。
- 游戏规则、原版数值和DATA_VERSION保持不变；材料推荐、重复实例校验、占用保持及准备/战斗权限仍由引擎负责。
- 弹窗记录打开前的暂停状态，合成预览沿用该记录，不将弹窗导致的暂停误当作用户手动暂停。提交成功后关闭；失败则保留弹窗及错误提示。地图点击只负责选中，必须另按操作按钮才打开弹窗。
- 保留按钮调用共用的 `keepAndStartWave`，验证通过后启动当前准备的波次。保留后关闭弹窗时覆盖准备阶段的旧暂停，前台开始模拟；失败不部分消耗候选，连点不能重新启动战斗。

## 验证限度

上述界面实操在桌面浏览器中设置手机视口尺寸完成；Pointer Events多指与中断流程使用自动事件测试。配方实例去重、未选中的重复材料保留和战斗合成占用不变由既有规则测试覆盖；本次已在浏览器中完成同种替代材料切换。地图为正方形，全图等比显示时长屏会有留白，可按需放大。

尚未连接安卓真机，不能视为完成触屏硬件、浏览器地址栏伸缩、软键盘、手势返回、刘海区域和长期性能验收。没有增加APK或离线缓存。公开测试沿用[GitHub Pages](https://ruiz1996.github.io/gem_td/)，部署以[Actions](https://github.com/ruiz1996/gem_td/actions)结果为准。
