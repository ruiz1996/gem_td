# 全免疫波仍有伤害：统计、外部技能与版本边界

查阅日期：2026-09-08。承接[免疫与第23波核查](immunity-audit.md)。依据仍为2018固定快照 `712f6a2d0f68ea4049e8923917311f8d1a44dfc8`，没有在用户所玩的Dota客户端重放。

用户明确确认：整波都是对应免疫时，铀235在物免波、古代鸡血石在魔免波仍在造成伤害；随后补充没有其他技能也会发生。因此混合波、英雄链接和其他外部增益均不作为这次现象的解释。此前“未找到两塔固有技能穿透”只限定静态技能，不能扩大成“原版实战不可能出现”。

目前的关键缺口在塔自身Lua伤害路径和目标版本的免疫结算。铀附加箭以`ApplyDamage`制造物理伤害，没有执行新的普通攻击；物免使用物理承伤百分比属性，而非绝对禁止物理伤害。需要验证该属性是否同样拦截这条脚本路径，不能只看到`PHYSICAL`便推定结果。古代鸡血石还需同时核对Lua技能免疫门槛与显式100魔抗。这些是待验证问题，未完成原客户端复现。

## 统计是否虚记免疫伤害

[怪物配置345–354行](https://github.com/clementbera/Website/blob/712f6a2d0f68ea4049e8923917311f8d1a44dfc8/GemTD-Generation/scripts/npc/npc_abilities_custom.txt#L345)在`OnTakeDamage`中把`%attack_damage`传给`show_damage`。[统计函数6848–6892行](https://github.com/clementbera/Website/blob/712f6a2d0f68ea4049e8923917311f8d1a44dfc8/GemTD-Generation/scripts/vscripts/addon_game_mode.lua#L6848)取整、把负值截成0，再按伤害来源累加，没有根据面板攻击力补算未生效伤害。

[ModDota作者的事件实验](https://moddota.com/abilities/datadriven/all-about-the-target/#damage)区分了同名事件参数：`OnTakeDamage`收到减免后伤害，`OnAttackLanded`收到减免前攻击值。不能只看到`%attack_damage`就认为统计记录了减免前伤害。该实验是历史数据驱动事件的开发者实测，不是本项目对目标客户端的实测。

服务器在波末发送最终统计后清空表（主Lua5647–5649行）。客户端可能暂留上波表，但无法解释本波中持续增长。统计未按目标剩余HP截断；即使存在过量伤害统计，也不能把完全免疫的0伤害凭空变大。

## 优先验证铀的普通攻击与脚本伤害是否分开处理

[附加箭函数125–139行](https://github.com/clementbera/Website/blob/712f6a2d0f68ea4049e8923917311f8d1a44dfc8/GemTD-Generation/scripts/vscripts/lua_ability/fenliejian.lua#L125)读取攻击力后调用`ApplyDamage`，没有调用`PerformAttack`。物免[5487–5506行](https://github.com/clementbera/Website/blob/712f6a2d0f68ea4049e8923917311f8d1a44dfc8/GemTD-Generation/scripts/npc/npc_abilities_custom.txt#L5487)用的是`INCOMING_PHYSICAL_DAMAGE_PERCENTAGE=-100`，不是`ABSOLUTE_NO_DAMAGE_PHYSICAL`。两者都是可用但不同的[修饰器属性](https://moddota.com/abilities/ability-keyvalues/)。

这提出一个可以实验判别的假设：如果前一个属性在对应Dota版本只作用于普通攻击类伤害，那么铀的主箭可能为0，而脚本附加箭仍能造成物理伤害。这样的穿透不需要钻石被动、纯粹伤害转换或英雄技能。

**尚未取得目标版本的一手实验或引擎源码证明这个“如果”。**枚举名称、脚本测试函数的存在都不等于实际结算证据。也不能把此假设直接实现为“所有物理法术都穿透”，或套用于古代鸡血石的魔抗问题。

## 已排除的本局解释：英雄链接（保留源码机制供查询）

用户已确认没有其他技能也会造成伤害，因此下述链接机制不能解释本次反馈。保留它用于区分伤害来源和统计归属，避免后续重复调查。

[链接技能12619–12680行](https://github.com/clementbera/Website/blob/712f6a2d0f68ea4049e8923917311f8d1a44dfc8/GemTD-Generation/scripts/npc/npc_abilities_custom.txt#L12619)给友方远程单位挂60秒增益，施法冷却5秒、射程500，最高4级。增益监听被加持单位的`OnAttackLanded`，将攻击值、攻击者、施法者传给Lua。

[链接Lua144–201行](https://github.com/clementbera/Website/blob/712f6a2d0f68ea4049e8923917311f8d1a44dfc8/GemTD-Generation/scripts/vscripts/lua_ability/fenliejian.lua#L144)随后：

1. 在怪物队伍中全图查找属于同一玩家的怪物；意图选离本次目标最远的一只。如果选中的仍是本次目标，则退出。
2. 按攻击事件值的70%／80%／90%／100%计算额外伤害。
3. 使用`DAMAGE_TYPE_PURE`结算，`attacker`仍设为发动攻击的塔。因此额外伤害可以计入该塔统计，而非英雄统计。

结合上述事件实验，可形成一个有条件的机制推断：被链接加持的铀235命中物免怪A，普通物理部分为0，但事件仍提供减免前攻击值，于是对另一只怪B结算纯粹伤害，伤害归铀235。按无其他增益的220攻击、4级链接举例，名义链接伤害为220，而非从0物理实伤计算出0。此推断不适用于用户已确认的无外部技能条件。

古代鸡血石若也有该增益，同样可能产生归在其名下的纯粹伤害；它的普通物理攻击本来也不被魔免阻挡。这些不能解释用户已确认的无外部技能条件，也不能据此说2500点叉状闪电已穿透魔免。

边界：

- 用户明确没有其他技能也会发生，因此已排除链接作为本次原因。
- 链接需要另一只合格怪物，只有一只怪时不会产生这段伤害。
- 铀附加箭是`ApplyDamage`，不是新的一次普通攻击；没有证据表明十支附加箭各自触发链接。
- 链接搜索以坏人队伍为基准、目标为友方，`FLAG_NONE`不能直接按“排除魔免敌人”解释。最终纯粹伤害能否通过目标版本的技能免疫门槛仍需客户端验证。
- 项目首版按用户要求没有英雄技能，所以尚不包含这个外部伤害来源。不能为了匹配有英雄增益的原版体验，直接给所有铀235增加无条件穿透。

## 古代鸡血石的Lua路径需要继续核实

[Shock脚本](https://github.com/clementbera/Website/blob/712f6a2d0f68ea4049e8923917311f8d1a44dfc8/GemTD-Generation/scripts/vscripts/lua_ability/shock.lua#L1)直接对主目标调用`ApplyDamage`，再以坏人队伍的友方搜索取得附加目标。伤害表没有传入`ability`对象，也没有忽略魔抗旗标。

这意味着仅凭KV中的`SPELL_IMMUNITY_ENEMIES_NO`，不足以断言每次Lua伤害都必定被技能免疫门槛拦截；但**能选中、能调用伤害函数，也不等于能绕过100魔抗**。旧`enemy_momian`同时显式设置魔免状态和+100魔抗，两层必须分别查。

Valve[7.23官方更新](https://www.dota2.com/outlanders)改过技能免疫与魔抗的关系，说明引擎版本不能忽略；这并不会自动抹掉GemTD自己写下的+100魔抗属性。不能用现代BKB规则直接证明旧地图的叉状闪电穿透。

## 其他解释的核查结果

| 候选 | 当前证据与限制 |
| --- | --- |
| 钻石加攻被动穿物免 | 仍无支持：只加基础攻击力，未新增伤害事件或转换类型。 |
| MVP减魔抗／虚无破魔免 | 原MVP敌方光环Flags为NONE，虚无配置不穿魔免；没有找到可直接清除魔免的完整链路。不能把−70简单加到100上，就宣布破免。 |
| 恐吓增伤抵消物免 | 恐吓使用通用承伤百分比，物免使用物理承伤百分比，属于不同属性，不能凭名称相近就按−100+50相加。 |
| 石化使物免恢复承伤 | 翡翠魔像会调用原生`medusa_stone_gaze`，效果依赖Dota引擎；未验证其与−100物理承伤的结算顺序，暂不能作为结论。 |
| 破被动／驱散免疫 | 已检索缓存中的免疫修饰器移除、Purge及被动禁用相关路径，未找到对应完整机制。候选建造塔自身禁用被动与敌人免疫无关。 |
| 代理施法导致归属错误 | `father`归属映射存在，但找到的设置点是翡翠魔像的冰霜链代理，不能据此解释铀235和古代鸡血石。链接则是另一条明确的外部技能归属路径。 |
| 全局伤害重写／直接扣HP | 已缓存的主Lua及相关技能文件未检出SetDamageFilter或与两塔相关的SetHealth／ModifyHealth绕过路径；检出的直接设血主要用于出生血量与基地生命同步。该结果只覆盖已取得文件。 |
| 用户玩的游廊版本不同 | 仍然可能。2018快照不是所有年份的原版；当前工作坊简短更新记录不足以确定差异内容。 |

## 当前决定与验证缺口

本轮只修订研究结论，不改战斗数值。完整结论应是：**用户已排除混合波与外部技能；当前2018静态快照尚不足以解释其观察。需要核对两塔脚本伤害、攻击与法术来源类别、以及当时的免疫实现。现版按伤害类型直接归零的模型仍待验证，不能用本模拟器的结果反证原版体验。**

下一步有效验证需要对应版本VPK或Dota客户端：在整波同类免疫且无外部增益的场景，分别记录普通攻击、铀的附加箭、古代鸡血石闪电和灼烧的HP差、伤害类别及统计增量；额外读取目标实际魔抗和免疫修饰器。这样才能区分攻击类物免、Lua技能权限、魔抗属性或地图版本变化。没有客户端实测前，不将其中任何一条直接写成已确认的原版规则。
