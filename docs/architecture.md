# 设计与技术方案

更新日期：2026-09-07。状态：下述主要结构已用于首个试玩版，设备测试尚未完成。实际差异与暂定参数见 [制作记录](implementation-status.md)。

## 技术方向

建议 TypeScript + Phaser 构建 2D 浏览器游戏。Phaser 官方文档说明支持手机及桌面浏览器的 WebGL/Canvas 渲染（[T01](research/sources.md#技术资料)）。具体引擎版本在实现前确认并锁定。

后续可评估 Capacitor 打包 Android 应用（T02）；此路径不是已完成的打包承诺。安卓浏览器兼容性、后台恢复和性能需要在目标设备验证。

## 三部分分离

| 部分 | 职责 | 边界 |
| --- | --- | --- |
| 规则层 | 阶段推进、棋盘占用、寻路、抽石、合成、攻击、效果和波次 | 不依赖 Phaser、DOM、像素坐标或音效 |
| 配置层 | 宝石、配方、怪物、地图、经济、概率、波次 | 保存来源与版本，缺失字段不默认为 0 |
| 表现层 | 棋盘绘制、动画、特效、面板、触屏输入、声音 | 发送操作请求并展示状态，不自行计算伤害 |

射程和距离使用规则层的世界单位或格子，时间使用统一时间单位。原版距离到棋盘格的比例必须核实并集中定义，不能把原版射程数值直接当像素使用。

换主题和精灵素材主要改表现层；换等距视角要改投影和点击映射；改为真正 3D 仍需重做镜头、渲染和交互。换地图尺寸或路标会影响路线与平衡，不属于纯美术替换。

## 核心状态建议

- 棋盘：格子坐标、可建造性、阻挡状态、内容实例 ID。
- 宝石实例：稳定 ID、类型、品质、坐标、放置序号、本轮候选或已保留状态。
- 运行状态：准备／战斗／结算／胜利／失败、当前波次、生命、经济、随机数状态。
- 敌人：属性、位置、路标进度、状态效果、存活状态。
- 暂停和倍速作为运行控制，不改变建造权限。

## 合成事务

合成请求包含配方 ID、成品位置对应的材料实例 ID、其余材料实例 ID。

确认时检查阶段权限、材料存在性、类型与品质、实例去重、配方条件及成品位置。全部检查通过后原子性执行替换；任一失败均不部分消耗。

战斗合成前后，对棋盘阻挡集合做一致性验证。路径依据阻挡和路标计算，不能依据格子内容是塔还是石头计算。

材料候选默认按放置序号稳定排序，并用实例 ID 作为相同序号下的确定性排序依据。候选规则不得混淆未保留的本轮宝石与此前已保留的塔。

## 时间和战斗

建议使用固定模拟步长，绘制可独立插值。倍速改变单位现实时间推进的模拟时间，避免不同帧率产生不同攻击次数。

随机抽石和随机战斗效果使用可保存的随机状态，以便复现问题。具体随机分布仍按原版核实，固定种子本身不意味着概率正确。

地面路径在准备阶段占用变化后重新校验，战斗期间保持占用固定。飞行路线、转角与路标推进逻辑需独立验证。

## 存档

建议记录存档结构版本、数据配置版本、模拟时间、阶段、地图、塔、敌人、状态效果及随机状态。

准备阶段和波次结束是优先保存点；如支持战斗中续玩，需要包括冷却、投射物等完整战斗状态。恢复旧存档时不得悄悄套用新数值。

安卓切换后台时暂停，返回时避免一次性补算大量战斗时间；最终行为以实机验证结果为准。

## 手机与桌面操作

两套界面共用规则引擎和存档。自动模式根据视口尺寸及触屏能力选择；用户也可手动覆盖。竖屏以底部固定面板操作，横屏以右侧面板操作。镜头初始按约30 CSS像素一格放大，另有全图入口；逐格方向按钮、候选按钮和宝石列表减少精确点击小格子的需要。合成预览以原生选择框展示材料槽与具体实例坐标。

输入由单一原生Pointer Events处理器接管，区分点击、拖动、双指手势及取消事件。相机与操作偏好不进入规则存档，不改变阶段权限或数值。结构、边界与测试详见[手机交互设计](../game/docs/touch-interaction.md)。

## 验证标准

| 范围 | 需要证明的行为 |
| --- | --- |
| 建造与路径 | 不可堵死任何必经段；暂停时仍不能在战斗中改路 |
| 合成 | 配方条件准确、材料可选且不重复、取消无副作用、占用集合不变 |
| 战斗 | 攻击间隔、伤害类型、护甲、减速、光环和触发规则可解释且与基线一致 |
| 时间 | 相同操作与种子下，不同渲染帧率及倍速产生一致的模拟结果 |
| 存档 | 续玩与不中断运行在同一模拟时点状态一致 |
| 平衡 | 多个固定种子、布局及配塔策略下记录漏怪、生命和各塔输出，查找难度突变 |
| 安卓体验 | 检查缩放、拖动、点击、暂停恢复、存档与典型高负载波次 |

自动模拟可揭示数值问题，但不能替代真人试玩，也不能仅以某个脚本策略通关作为整体平衡成立的证据。
